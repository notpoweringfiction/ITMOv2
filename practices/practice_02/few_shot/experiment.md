# Few-shot

- Артефакт Практики 1: tests_e2e.md и prompt_P1_02.md (evidence и ожидаемые статусы)
- Что хотим улучшить: убрать несоответствие ожиданий для отсутствующего поля diff; сделать примеры воспроизводимыми и однозначными

## Примеры

### Хороший результат

Запрос без поля diff, evidence prompt_P1_02, expected status 500, interpretation key error подтверждает отсутствие валидации поля diff.

### Плохой результат

Запрос без поля diff, evidence prompt_p1_2, expected status: 422, interpretation: поле diff корректно отклоняется валидацией.

## Запрос

Сформировать проверяемые e2e-сценарии на основе prompt_P1_02 OUTPUT checks:
- Позитивный: POST /api/reviews c корректным JSON {"diff": "..."}
- Негативный: POST /api/reviews с пустым JSON {}
- Граничный: POST /api/reviews с очень большим значением "diff"

## Что получили

Проверки приводят к ожидаемым результатам из prompt_P1_02:
- Негативный сценарий даёт 500 (KeyError), что подтверждает отсутствие валидации.
- Граничный сценарий демонстрирует рост латентности/возможные сбои (таймаут/500) из-за отсутствия ограничений.
