Рефлексия: две спеки — одна фича

Выбор SDD-фреймворка

- Использован BDD/Gherkin из-за простоты чтения и понятности сценариев Given/When/Then.
- Сопоставлено с OpenSpec: в этом задании Gherkin заменяет delta-specs; обе спеки согласованы до кода.

Что согласовали заранее

- Контракт данных: множество строк (имена), нормализация пробелов только при добавлении, порядок вывода — сортированный лексикографически.
- Контракт ошибок: пустое имя → ValueError/код возврата 1 с сообщением "empty name"; некорректный путь экспорта → ValueError с сообщением "invalid output path".
- API UI: команды subscribe/list/export; фильтр по префиксу (case-insensitive), export пишет видимый список.

Чему научились

- Чёткое разделение UI и логики снижает перетолковывание: CLI тонкий, все правила — в сервисе.
- Две спеки ускоряют ревью: дискуссии про формат/ошибки решаются до кода.
- Согласованный контракт позволил сразу написать тесты и избежать доработок интерфейса.

Сравнение с OpenSpec

- OpenSpec удобен для управления изменениями и history; Gherkin — для сценариев поведения.
- В более крупном проекте имеет смысл держать оба: OpenSpec — артефакты и процесс, Gherkin — executable specs.
